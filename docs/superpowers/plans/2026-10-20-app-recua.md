# O app recua — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No desktop, abrir um `Dialog`, um `AlertDialog`, a confirmação "Descartar alterações?" ou a busca faz o app recuar (98,5%, para o centro da tela), e o modal chega na frente quase parado (sobe 6px esmaecendo).

**Architecture:** Um contador de módulo (`src/lib/recuo.ts`) liga `data-recuo` no `<html>` enquanto houver modal aberto e grava a origem do recuo de cada região como `transform-origin` nela; o CSS (`globals.css`, do `md` para cima) escala `[data-slot=sidebar-container]` e `[data-slot=sidebar-inset]` por transição. Cada modal chama `useRecuoDoApp(aberto)`. A entrada do modal muda só classes (`md:`), e a de hoje fica em `max-md:`.

**Tech Stack:** React 19, Tailwind v4 (variantes `md:`/`max-md:`, `tw-animate-css`), vitest (`environment: "node"`: função pura e testes de fonte).

**Spec:** [`docs/superpowers/specs/2026-10-20-app-recua-design.md`](../specs/2026-10-20-app-recua-design.md) (com "Decisões de quem escreveu"). Protótipo: [`2026-10-20-app-recua/prototipo-aberturas.html`](../specs/2026-10-20-app-recua/prototipo-aberturas.html), variante `fundo`.

## Global Constraints

- Só do `md` (768px) para cima, por mídia de CSS. Abaixo, tudo como hoje (a mola com `zoom-in-95` e a cascata `dialog-reveal`, agora em `max-md:`).
- Números da spec: recuo **98,5%** em **300ms** abrindo e **200ms** voltando, `--ease-out`; modal **6px** de subida, **99%→100%**, **220ms**, **30ms** de atraso, fecha em **120ms** só esmaecendo; busca **30 / 60 / 90 + 20·i ms** de atraso.
- Movimento reduzido: sem recuo e sem subida; só esmaece.
- Nada inline nem `data-recuo` sobra depois de fechar; montar fechado não recua.
- A pílula da busca entra pela lista do feixe (`--command-beam-intro`); nada de `animate-in` nela (rodada 323).
- `src/components/ui/`, `src/app/globals.css`, `src/app/designsystem/` pedem confirmação do harness: o dono autorizou.
- Comentários em português, no tom dos arquivos. Verificação: `npx tsc --noEmit && npm run lint && npm run test:unit`. Prévia: `dev-attach` (o `next dev` em :3000; nunca subir outro), ≥ 1024px de largura, página **rolada**; banco de produção: não gravar nada.

## Review Focus

1. **Página rolada**: abrir um diálogo com a página rolada não pode pular nada; o conteúdo encolhe para o centro do que está à vista. → conferência na prévia (Tarefa 1) e o teste puro da origem.
2. **Dois modais empilhados** (um `AlertDialog` de dentro de um `Dialog`, ou o "Descartar alterações?"): o app recua uma vez e só volta quando o último fecha. → teste puro do contador (Tarefa 1).
3. **Fechar no meio do recuo e reabrir**: a transição segue de onde está, sem salto. → é da transição de CSS; conferência na prévia.
4. **Janela que atravessa 768px com um modal aberto**: nada fica recuado no telefone (a regra é de mídia). → teste de fonte (Tarefa 1: o CSS do recuo mora dentro de `@media (width >= 48rem)`).
5. **O cabeçalho volta a borrar depois de fechar** (o `transform` no ancestral desliga o `backdrop-filter` dele enquanto dura). → conferência na prévia (Tarefa 1): sem `transform` computado no `sidebar-inset` depois do fechamento.

### Task 1: O app recua

**Files:**
- Create: `src/lib/recuo.ts`, `src/lib/recuo.test.ts`, `src/hooks/use-recuo-do-app.ts`
- Modify: `src/app/globals.css` (um bloco novo do recuo, perto dos outros de movimento, fora da faixa que o `glass.test.ts` reserva)

**Interfaces:**
- Produces:
  - `export function origemDoRecuo(caixa: { left: number; top: number }, tela: { width: number; height: number }): { x: number; y: number }` — o centro da tela nas coordenadas da caixa: `{ x: tela.width / 2 - caixa.left, y: tela.height / 2 - caixa.top }`.
  - `export function abrirRecuo(): () => void` — soma 1 ao contador; no primeiro, mede `[data-slot=sidebar-container]` e `[data-slot=sidebar-inset]` (`getBoundingClientRect`, `innerWidth`/`innerHeight`), grava `style.transformOrigin = "<x>px <y>px"` em cada um e liga `document.documentElement.dataset.recuo = ""`. Devolve a função que fecha: subtrai 1; no último, tira o `data-recuo` e, no fim da transição de volta (`transitionend` de `transform` em cada região, ou 200ms de reserva), limpa o `transformOrigin` — a não ser que outro modal tenha reaberto nesse meio. Idempotente: chamar a função de fechar duas vezes não desconta duas.
  - `export function useRecuoDoApp(aberto: boolean): void` em `src/hooks/use-recuo-do-app.ts` — `useLayoutEffect` que chama `abrirRecuo()` quando `aberto` e devolve o fechamento.
- CSS: dentro de `@media (width >= 48rem)` e `(prefers-reduced-motion: no-preference)`: `:is([data-slot=sidebar-container], [data-slot=sidebar-inset]) { transition: transform 200ms var(--ease-out) }` e `:root[data-recuo] :is(...) { transform: scale(0.985); transition-duration: 300ms }`.

- [ ] **Step 1: Testes que falham** (`src/lib/recuo.test.ts`):
```ts
expect(origemDoRecuo({ left: 0, top: 0 }, { width: 1280, height: 800 })).toEqual({ x: 640, y: 400 })
expect(origemDoRecuo({ left: 256, top: -1200 }, { width: 1280, height: 800 })).toEqual({ x: 384, y: 1600 })  // o conteúdo rolado 1200px
```
O contador, com um `document` falso mínimo (um objeto com `documentElement.dataset` e `querySelectorAll` devolvendo `[]`; injete-o — `abrirRecuo` aceita `doc = document` como parâmetro opcional para o teste): duas aberturas e um fechamento deixam `dataset.recuo === ""`; o segundo fechamento tira; chamar o mesmo fechamento duas vezes não tira antes da hora. De fonte: o bloco do recuo no `globals.css` está dentro de `@media (width >= 48rem)` e contém `scale(0.985)`, `300ms` e `200ms` (Review Focus 4).
